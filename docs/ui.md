# 画面設計

画面はスマホ幅（390px）を基準に、トップページ・参加者用・主催者用の計 7 画面と、利用規約・プライバシーポリシーとする。実際に触れるモックアップは [LeacTion! 画面設計](https://claude.ai/artifact/An4BdqKfAU6AMHnF2Xwdg3) にある。

## 画面一覧

| 画面 | パス | 要点 |
| --- | --- | --- |
| トップページ | `/` | サービスの説明、使い方、よくある質問、「イベントを作る」ボタン |
| イベントページ | `/e/:id` | コメント一覧、発表切り替えバー、入力欄。発表一覧と共有は下から出るシート |
| イベント作成 | `/new` | 名前・開催日・発表枠。URL とハッシュタグは折りたたみ |
| 作成完了 | `/new`（作成直後の状態） | 参加者用 URL と作成者用 URL。保存確認できるまで次へ進めない |
| 管理：発表枠 | `/e/:id/manage` | 並べ替え、追加、編集。操作ごとに即時保存 |
| 管理：コメント | 同上（タブ） | 受付スイッチ、非表示・再表示、投稿者単位の一括非表示 |
| 管理：基本情報・管理者 | 同上（タブ） | 管理者タブは作成者にだけ表示。共同管理者 URL と削除 |
| 利用規約 | `/terms` | 運営者は mather。準拠法は日本法、管轄は東京地裁 |
| プライバシーポリシー | `/privacy` | Cookie・localStorage、アクセス解析、外部送信（Turnstile、Google Fonts） |

## トップページ

現行版のトップページ（キャッチコピー → 作成ボタン → LeacTion! とは → 3 つの理由）を引き継ぎ、アカウント不要になった点に合わせて書き直す。

1. **ヒーロー**: キャッチコピー「発表に、その場でひとこと。」、1〜2 文の説明、「イベントを作る」ボタン、「無料・アカウント登録なしで作れます」
2. **できること（3 項目）**: 参加者はログイン不要 / 発表ごとにコメントと「いいね」 / 主催者も URL だけで管理
3. **使い方（3 ステップ）**: イベントを作る → URL か QR コードを共有する → 当日はコメントを楽しむ
4. **よくある質問**: 料金、管理用 URL をなくしたとき（再発行不可。共同管理者 URL があれば管理を続けられる）
5. **もう一度「イベントを作る」ボタン**
6. **フッター**: 利用規約、プライバシーポリシー、お問い合わせ（フォーム、新しいタブ）、GitHub

OGP はサービス共通のもの（タイトル「LeacTion!」、説明文、共通の画像）を使う。イベントページの OGP はイベント名・開催日・イベント名入りの画像に差し替える（[architecture.md](architecture.md) の「OGP 画像」）。

## イベントページ

上から順に、ヘッダー・発表切り替えバー・感想・コメント一覧・入力欄の 5 段。

- **ヘッダー**: ロゴ（小）、イベント名（1 行で省略）、共有ボタン、メニューボタン。ロゴとイベント名はリンクにしない（現行版はロゴが 1 タップでトップへ移動していた）
- **メニューシート**: 「LeacTion! について・イベントを作る」（新しいタブでトップページを開く）、「利用規約」「プライバシーポリシー」（新しいタブ）と、「イベントを管理する」（その端末に管理セッションがあるときだけ表示）
- **発表の切り替え**: 上部のバーに「‹ 2/5 · 発表者／タイトル ›」を常に表示する。隣へは矢印で 1 タップ、離れた発表へは中央を押して一覧シートから選ぶ。一覧シートには発表ごとのコメント数を出す。選んだ発表は `?tid=` に反映する（`history.replaceState`）
- **感想**: 発表切り替えバーの下に、選んでいる発表への感想の枠を置く。詳細は下の「感想」
- **コメント一覧**: 新しいものが下に積まれる。カードは本文・時刻・右端のいいねボタン（件数付き）。自分のコメントには「あなた」ラベルと削除ボタンを付け、いいねボタンは無効
- **新着ピル**: 最下部以外を見ているときに新着が来たら、入力欄の上に「新着コメント n 件」を出す。押すと最下部へ移動
- **入力欄**: 画面下に固定。プレースホルダを「○○さんの発表にコメント」にし、どの発表に書き込むかを明示する。スマホは Enter で改行、PC は Shift+Enter（⌘/Ctrl+Enter も可）で送信。空のときは送信ボタンを無効にする。`font-size` は 16px 以上（iOS の自動ズーム防止）
- **初回の案内**: そのブラウザで初めてイベントページを開いたとき、入力欄の上に「コメントは、このページの URL を知っている人なら誰でも見られます。他人の権利を侵害する内容や、言葉づかいに気をつけてください。送信すると、利用規約とプライバシーポリシーに同意したものとみなします」と「OK」ボタンを出す。QR コードなどで招待された参加者は作成画面の同意文を見ていないため。画面を塞ぐダイアログにはせず（参加者に制限を感じさせない）、閲覧はそのまま続けられる。「OK」を押すか最初のコメントを送ったら localStorage（`leaction:noticeAck`）に記録して以後は出さない。規約を改定したら記録の版を変えて出し直す。リンクは新しいタブで開く。受付停止中は出さない
- **空の状態**: 「まだコメントはありません。最初のひとことをどうぞ。ログインは不要です。」
- **発表中バッジ**: 管理者が設定したときだけ表示し、未設定なら何も出さない
- **受付停止中**: 入力欄の代わりに「コメントの受付は停止中です」を出す
- **アーカイブ済み**: 入力欄の代わりに「このイベントはアーカイブされています。コメント・いいね・感想の受付は終了しました」を出す。いいねボタンは件数だけを表示して押せなくする。感想は割合と票数だけを表示して押せなくする。自分のコメントの削除ボタンは残す
- **共有シート**: QR コード（端末内で生成）、URL とコピーボタン、「X でポスト」（イベントのハッシュタグがあればそれと、常に `#leaction` を付ける）「他のアプリで共有」（Web Share API。非対応ブラウザでは出さない）。共有する URL には経路ごとに `?src=`（`qr` / `link` / `x` / `share`）を付ける（[analytics.md](analytics.md)）
- **リンク**: コメント内の URL はリンク化し、押すと「この URL を開こうとしています」の確認を出す

### 感想

発表への感想を 4 種類から 1 つ選んで送る。コメントを書くほどではない人も反応でき、登壇者や主催者は割合と票数で盛り上がりを確かめられる。モックは [感想ボタンのモック](https://claude.ai/artifact/PwM69C9wj7TCdHgp9nR6v6)。

| 種類 | ラベル | マウスオーバー・読み上げ | アイコン | 色 |
| --- | --- | --- | --- | --- |
| `useful` | ためになる | ためになる | 電球 | `--r-useful` |
| `fun` | おもしろい | おもしろい | 笑った口の吹き出し | `--r-fun` |
| `try` | 試したい | 試したい | フラスコ | `--r-try` |
| `more` | くわしく | くわしく知りたい | 虫めがね | `--r-more` |

- **見た目**: 枠の見出し「この発表の感想」と票数（「38 票」）、割合の積み上げ横棒、4 つのボタンを縦に並べる。ボタンはアイコン・ラベル・割合（％）を縦に並べたもので、全体が押せる範囲になる。割合は合計が 100% になるよう最大剰余法で丸める
- **投票**: 発表ごとに 1 人 1 票。押すと投票、選んでいるボタンをもう一度押すと取り消し、別のボタンを押すと付け替える。選んでいるボタンは `aria-pressed="true"` にし、アイコンを塗りつぶして枠と地を感想の色にする
- **票がないとき**: 横棒を `--line` の色だけにし、割合は「—」、案内は「まだ感想はありません。最初の 1 票をどうぞ」
- **畳む**: 見出しを押すと開閉する（`aria-expanded`）。畳んでいる間も見出しの行に小さな横棒と票数を出す。開閉は localStorage（`leaction:reactionsOpen`）に覚え、発表やイベントをまたいで保つ。初期状態は開く
- **受付**: いいねと同じに扱う。コメントの受付停止中も感想は送れる。アーカイブ後は割合と票数だけを表示し、ボタンを `disabled` にして薄く表示する。自分の票は選んだ状態のまま見せ、案内は「感想の受付は終了しました」
- 参考にした他サービスの絵柄（円い顔のキャラクター、円の下側を塗って割合を入れる表現）には寄せない
- 実装時はプライバシーポリシー（`Privacy.tsx`）の「取得する情報」の投稿に感想を、保存する情報の一覧に `leaction:reactionsOpen` を足す

### 不意の離脱を防ぐ

イベント中に誤タップでイベントページを離れないよう、次の 3 段で防ぐ。

1. **外へ出る導線は 1 タップで発火させない**: トップページへのリンクはヘッダーに置かず、メニューシートの中に入れる（2 タップ）
2. **外へ出る導線は新しいタブで開く**: トップページ、コメント内の URL、X での共有はすべて `target="_blank" rel="noopener"`。イベントページ自体は残るので、戻る操作が要らない
3. **未送信のコメントがあるときだけ警告する**: 入力欄が空でないときに限り `beforeunload` を登録し、ブラウザ標準の確認を出す。アプリ内の画面遷移（管理画面へ移るなど）は Solid Router の `useBeforeLeave` で同様に確認する

常に `beforeunload` を出す方式は採らない。確認が毎回出て煩わしいうえ、スマホのブラウザでは確実に表示されないため。

## イベント作成

- 項目: イベント名（必須）、開催日（必須）、発表枠（発表者・タイトル、初期 2 枠、「発表枠を追加」で増やす）
- 「イベントページ URL・ハッシュタグ（任意）」は折りたたみ
- 画面下に固定の「イベントを作成」ボタン。送信時に Turnstile を通す
- ボタンの下に「作成すると、利用規約とプライバシーポリシーに同意したものとみなします」。リンクは入力中のフォームを残すため新しいタブで開く

## 作成完了

- 参加者用 URL: 「会場や SNS で共有してください」とコピーボタン。URL には `?src=host` を付ける
- 作成者用 URL: 警告色の枠で囲み、「このURLをなくすと管理できなくなります。他の人には共有しないでください」と明記する
    - 続けて「ほかの人と一緒に管理するときは、管理画面の『管理者』タブから共同管理者用の URL を発行して渡す」ことを案内する（作成者用 URL を共有させないため）
    - コピーボタン
    - 保存の手段はコピーボタンと分け、「コピー以外の保存方法」としてボタンごとに説明を添えて縦に並べる（同じ見た目のボタンが横に並ぶと違いが分かりにくいため）
    - 「テキストファイルで保存」ボタン: イベント名・作成者用 URL・参加者用 URL を書いたテキストファイルをダウンロードする。端末にメーラーが関連付けられていなくても動く
    - 「他のアプリに送る」ボタン: Web Share API（`navigator.share`）で同じ内容を渡し、メモアプリやメールアプリ、自分宛てのチャットなどに送れるようにする。対応ブラウザ（主にスマホ）でだけ出す
    - `mailto:` は使わない。ブラウザ版 Gmail などを使っていてメーラーが関連付けられていない環境では何も起きないため
    - 「URL をブックマーク・保存しました」チェック。チェックするまで「イベントページへ」には進めない
        - ボタンは `disabled` にせず、薄い見た目（`aria-disabled`）のまま押せるようにする。`disabled` だと押しても何も起きず、チェックが必要だと気づけないため
        - ボタンの下に「上の『保存しました』にチェックを入れると進めます」と添える
        - 未チェックで押したら、チェック欄までスクロールしてフォーカスを移し、枠を警告色にして「URL を保存したら、チェックを入れてください」と出す
- この画面を閉じると作成者用 URL は二度と表示できない（ハッシュしか保存しないため）

## 管理画面

- ヘッダー: 戻るボタン、イベント名、権限バッジ（「作成者」または「共同管理者」）
- タブ: 発表枠 / コメント / 基本情報 / 管理者（管理者タブは作成者のみ）
- 保存ボタンは置かず、操作ごとに即時反映する。失敗時はトーストで知らせて元に戻す
- アーカイブの案内（タブの上に帯で出す）
    - アーカイブ前: 「10/14 0:00 に自動でアーカイブされ、コメントといいねの受付を終了します」。開催日を変えると日時も変わる
    - アーカイブ後: 「このイベントはアーカイブされています」。作成者には「アーカイブを解除」ボタン（「解除すると 7 日間、コメントと編集を再開できます」と確認する）、共同管理者には「解除は作成者に依頼してください」を出す。発表枠・基本情報の編集と、コメント受付のスイッチは無効にする。コメントの非表示・再表示と、管理者タブの操作はそのまま使える

### 発表枠タブ

- ドラッグハンドルで並べ替え、行を押して発表者・タイトルを編集、「発表枠を追加」
- 「発表中」を導入する場合は、各行に「発表中にする」ボタンを置く（選べるのは 1 つ）
- 削除時は「この発表のコメント n 件も削除されます」と確認する

### コメントタブ

- 「コメントを受け付ける」スイッチ
- コメントを新しい順に表示。各行に発表名・時刻・投稿者 ID の先頭 4 文字。発表で絞り込める。「最新にする」で読み込み直す
- 「非表示にする」／「表示に戻す」、「この投稿者をすべて非表示」（確認を挟む）／「この投稿者の非表示を解除」
- 非表示のコメントは破線の枠で薄く表示し、参加者には見えていないことを示す

### 基本情報タブ

- イベント名、開催日、イベントページ URL、ハッシュタグ。フォーカスが外れたときに保存

### 管理者タブ（作成者のみ）

- 共同管理者 URL の一覧（名前、発行日、無効化済みかどうか）、無効化。無効化の確認には名前を出し、どの URL を止めるのかわかるようにする
- 「新しい共同管理者 URL を発行」: シートで名前（渡す相手や用途。例「運営 佐藤さん」「配信担当」）を入力させてから発行する。名前は必須。発行直後に一度だけ URL を名前と一緒に表示する
- イベントの削除（「削除後 7 日間は、この作成者 URL から復元できます」）
- 削除後に管理画面を開くと、削除済みであることと復元の期限、復元ボタン、トップページへのリンクを出す

## 利用規約・プライバシーポリシー

- 文面は `src/client/pages/Terms.tsx`・`Privacy.tsx` に直接書く。見出し・段落・表の共通の枠は `components/LegalPage.tsx`
- 表はスマホ幅では行ごとの縦積みにする（横スクロールさせない）
- 問い合わせ窓口はフォーム（`src/client/lib/site.ts` の `CONTACT_FORM_URL`）
- プライバシーポリシーは、保存する情報（Cookie・localStorage・D1・Analytics Engine）や外部送信先を変えたら合わせて直す。Cloudflare Web Analytics を有効にするときも追記する
- 文面を変えたら改定日を足す。利用規約の変更は、効力が生じる日より前にサービス上で知らせる（利用規約 第12条）
